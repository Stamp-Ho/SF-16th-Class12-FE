# 보드게임 작업 기록

- 작성 시각: 2026-09-25 13:08 KST (04:08 UTC)
- 범위: 보드게임 화면과 조작 흐름 점검 및 개선 사항 기록

## 현재 구조

- 보드게임 화면은 `/boardgame`에서 `BoardGameMain`과 `DiceArena`를 렌더링한다.
- 보드 타일은 `BoardTileData` 타입으로 관리하며, 클라이언트의 `Map<string, BoardTileData>` 상태에 담긴다.
- Three.js와 cannon-es로 보드, 주사위, 팀 말을 구성한다.
- 타일 편집 내용은 현재 브라우저 메모리 상태에만 반영된다. 새로 접속한 브라우저에서 같은 편집 내용을 보거나 여러 사람이 함께 편집하려면 서버 저장과 변경 동기화가 추가로 필요하다.

## 이번 작업

### 말 겹침 방지

- 시작 위치에는 팀별 오프셋이 있었지만, 이동과 워프에서는 타일 중심으로 말이 이동해 같은 칸에서 겹쳤다.
- `getPawnPosition` 공통 계산을 적용해 초기 배치, 이동 애니메이션의 목표 위치, 워프 위치에 팀별 오프셋을 사용하도록 했다.

### 키보드 조작

- WASD 입력을 `KeyboardEvent.code` 기반으로 정규화해 대소문자와 키보드 입력 상태에 관계없이 인식하도록 했다.
- Q/E를 누르고 있는 동안 카메라를 좌우 회전하고, Z/X로 확대·축소하도록 했다.
- 줌 값에 최솟값과 최댓값을 적용했다.
- 화면 하단에 키보드와 마우스 조작 안내를 표시한다.

### Space 중심 플레이와 팝업 처리

- 플레이 모드에서 Space를 누르면 주사위를 굴린다. 입력란이나 다른 버튼에 포커스가 있을 때는 단축키를 가로채지 않는다.
- 팝업이 열리면 확인 버튼에 포커스를 이동한다. 확인 버튼은 Space 입력으로 활성화할 수 있다.
- 이동 이벤트 팝업에도 확인 버튼을 제공한다. 기존 자동 실행 카운트다운은 유지되며, 확인을 누르면 바로 실행된다.
- 주사위 굴리기 허용 조건을 주사위 정지, 말 이동 완료, 타일 팝업 닫힘, 알림 팝업 닫힘으로 제한했다.
- 주사위 굴리기 함수에도 중복 입력과 팝업 상태 검사를 추가했다.

## 서버 저장 및 동시 편집 검토

- 보드 전체를 JSON 한 행으로 저장하면 구현은 간단하지만, 동시 편집에서 마지막 저장이 다른 편집 내용을 덮어쓸 수 있다.
- 현재 수정 흐름이 타일 단위이므로 보드 메타 정보와 타일 행을 나누고, 타일의 액션 파라미터처럼 유연한 필드에는 JSONB를 사용하는 구성을 권장했다.
- 저장 및 실시간 동기화는 아직 구현하지 않았다. 적용 시 타일별 버전 또는 갱신 시각을 이용한 충돌 감지와 Supabase Realtime 구독을 함께 설계할 필요가 있다.

## 2026-09-26 추가 작업 (23:01 KST / 14:01 UTC)

### 편집 모드와 격자

- 편집 모드에서 보드의 세로(행)와 가로(열)를 각각 3~20 범위로 설정할 수 있다. 적용 시 3D 보드를 다시 만들고 팀 위치와 턴을 초기화한다.
- 크기 변경 후에도 현재 보드 범위에 남는 타일은 ID 기준으로 편집 값을 보존한다.
- 편집 모드와 전체화면 토글을 우측 사이드바로 이동해 어느 모드에서든 접근할 수 있도록 했다.
- 편집 모드에서는 팀 Pawn을 숨긴다.

### 내부 타일 추가

- 편집 모드에서 `내부 격자 추가`를 누르면 보드 안쪽의 빈 칸이 표시된다.
- 빈 칸을 선택하면 `INNER` 타일을 생성하고 타일 속성 편집기를 연다. 생성한 내부 타일은 편집기에서 삭제할 수 있다.
- 보드 크기를 바꾸어도 내부 격자 범위 안에 있는 기존 내부 타일 설정을 유지한다.
- 현재 내부 타일은 편집 데이터로 생성된다. 말 이동 경로는 여전히 외곽 타일 순회만 사용하며, 내부 타일을 게임 경로에 연결하는 기능은 별도 작업이 필요하다.
