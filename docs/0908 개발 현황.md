# 0908 개발 현황

## 1. 프로젝트 개요

현재 프로젝트는 초기 기획서에서 제시한 “자리 배정 경매 + 관리자 기능”을 중심으로 시작했지만, 실제 서비스는 반 운영용 대시보드 형태로 확장되어 운영되고 있다.

초기 기획은 주로 경매 기능과 관리자 관리 중심이었지만, 실제 구현에서는 다음 기능들이 추가되며 서비스 범위가 넓어졌다.

- 자리 배정 경매
- 노래 큐
- 랜덤 순서 추첨
- 간식 센터
- 관리자 회원 관리
- 공지/외부 링크 관리
- 메인 대시보드 기반 접근

---

## 2. 초기 기획과 실제 서비스의 차이

### 2.1 기획안의 기본 방향

기획 문서의 핵심은 다음과 같았다.

- 26명 규모 소규모 반 인원 대상 서비스
- Admin과 User 역할 분리
- 메인 대시보드에서 링크/공지 관리
- 자리 배정 경매를 핵심 기능으로 설정
- 무작위 추첨 기능 제공
- 범용적인 경매 엔진 설계

### 2.2 실제 구현된 방향

실제 서비스는 위 기획을 유지하면서도 반 생활 운영 도구로 확장되었다.

- 메인 대시보드가 실제 서비스 진입점이 됨
- 좌석 배정 경매가 가장 핵심 기능으로 유지됨
- 노래 큐 기능이 추가되며 반 운영 특화 서비스로 발전
- 랜덤 추첨 기능이 실제 UI로 구현됨
- 관리자 권한이 세분화됨
- 간식 센터와 같은 부가 기능도 페이지로 추가됨

즉, 초기 기획은 “경매 기반 서비스”였고, 실제 서비스는 “반 운영 대시보드 + 실시간 행사 도구”에 가까운 형태다.

---

## 3. 실제 구현된 주요 기능

### 3.1 메인 대시보드

현재 메인 페이지는 [app/page.tsx](../app/page.tsx)에서 구현되어 있다.

주요 요소:

- 자리 배정 경매 카드
- 노래 큐 카드
- 제비뽑기 카드
- 간식 센터 카드
- 관리자 전용 페이지 접근
- 주요 링크/공지 링크 목록 표시

특징:

- 로그인 후 바로 대시보드가 화면에 출력됨
- 관리자 여부에 따라 관리 페이지 버튼 노출
- 외부 링크와 공지 목록을 카드 형태로 표시

기획과 달리, “서비스 랜딩 페이지” 역할이 실제로 매우 중요해졌다.

---

### 3.2 관리자 기능

관리자 관련 기능은 [app/admin/users/UserManagementTable.tsx](../app/admin/users/UserManagementTable.tsx)에 실제 구현되어 있다.

구현된 기능:

- 회원 목록 조회
- 이름 검색
- 회원 권한 변경
- 계정 활성/비활성 처리
- 비밀번호 초기화
- 일괄 회원 등록

추가된 점:

- 단순히 `admin` / `user`가 아니라 `super_admin`, `class_admin`, `song_admin`, `teacher` 등 역할이 세분화됨
- 운영상 필요한 권한 분리가 실제로 반영됨

이 부분은 초기 기획서에 비해 실제 운영 의도가 더 강하게 반영된 영역이다.

---

### 3.3 자리 배정 경매

현재 좌석 시스템은 [app/seats/SeatsMain.tsx](../app/seats/SeatsMain.tsx)에서 핵심 기능으로 구현되고 있다.

구현된 기능:

- 회차별 자리 배정 관리
- 좌석 배치도 표시
- 그룹 단위 좌석 점유
- 입찰 상태 및 금액 표시
- 관리자 제어 패널
- 실시간 데이터 반영
- 잠금/마감 상태 관리
- 행운 노리기 기능
- 스크린샷 모드 지원

추가된 운영 기능:

- 회차 단위로 관리
- `is_closed` 상태를 통한 마감 관리
- `is_gamble_enabled` 제어
- 좌석 점유 변동 시 경고 알림
- 유저별 현재 좌석/입찰가 요약

초기 기획의 “단순 A~M 구역 경매”를 넘어서, 실제 서비스는 운영용 좌석 경매 관리시스템 수준으로 발전했다.

---

### 3.4 노래 큐 기능

노래 큐는 초기 기획에 없던 서비스로, [app/song/SongMain.tsx](../app/song/SongMain.tsx)에 실제 구현되어 있다.

구현된 기능:

- 가수 대기열 추가
- 이유 입력
- 우선 예약 여부 선택
- 랜덤 뽑기
- 노래 검색 및 재생
- 노래 기록 기능
- 관리자 전용 무대 시작 제어
- 사용자별 차례 상태 확인

특징:

- 단순 기록 기능이 아니라 실시간 대기열 관리 기능으로 구현됨
- 반 운영에서 실제로 자주 쓰는 기능으로 보임
- 초기 기획에서 예상하지 못했던 “서비스 확장”의 대표 사례

---

### 3.5 랜덤 추첨 기능

현재 랜덤 순서 추첨은 [app/shuffle/ShuffleMain.tsx](../app/shuffle/ShuffleMain.tsx)에 구현되어 있다.

구현된 기능:

- 전체 인원 목록 로딩
- Fisher-Yates 셔플
- 애니메이션 기반 섞기 효과
- 순서 결과 표시

현재 상태:

- 사용자 경험 면에서는 잘 구현됨
- 다만 결과 저장/기록 기능은 기획 문서에 비해 실제 구현이 더 제한적이거나 비활성화된 상태로 보임

---

### 3.6 간식 센터

간식 페이지는 [app/snack/SnackMain.tsx](../app/snack/SnackMain.tsx)에 존재한다.

현재 상태:

- UI는 구성됨
- 간식 목록과 투표형 카드가 있음
- 하지만 기능은 아직 프로토타입 수준
- “토목공사 중” 문구가 남아 있어 아직 완성 단계가 아님

즉, 초기 기획서에서 말한 일반 경매/기본 대시보드 개념과는 다르게, 현재 는 “실험적 보조 기능”으로 남아 있다.

---

## 4. 기획서에는 있었지만 실제로는 제한적이거나 보완된 부분

### 4.1 일반 경매 기능

기획서에는 “일반 경매 목록”이 메인 대시보드에 포함될 예정이었지만, 실제 구현에서는 이를 직접적으로 확인하기 어렵다.

현재는:

- 자리 배정 경매가 메인 서비스로 확고하게 구현됨
- 일반 경매 물품 경매는 별도 페이지나 로직으로 연결되지 않음

즉, 범용 경매 엔진 설계는 계획으로 남아 있고, 실제 운용은 좌석 경매에 집중되어 있다.

---

### 4.2 DB 스키마와 실제 구현의 차이

기획 문서의 스키마는 다음 방향을 제시했다.

- `users`
- `dashboard_links`
- `seat_allocations`
- `bids`
- `random_draws`

하지만 실제 구현은 다음 구조를 사용하고 있다.

- `seat_rounds`
- `seat_groups`
- `seat_allocations`
- `seat_bid_histories`
- `song_records`

이 차이는 기획이 “범용 경매 엔진”을 중심으로 설계된 반면,
실제 서비스는 “실제 운영 로직에 맞춘 데이터베이스 구조”로 조정되었음을 보여준다.

---

## 5. 현재 서비스의 특징 요약

### 핵심 특징

- 메인 대시보드 중심 구조
- 역할별 권한 관리 강화
- 좌석 배정 경매가 핵심 기능으로 유지됨
- 노래 큐와 랜덤 추첨이 추가 기능으로 확장됨
- 관리자 페이지를 통한 운영 기능 강화
- 일부 부가 기능은 미완성 상태

### 변화의 방향

기획 초기: “경매 기반 자원 배분 서비스”

현재: “반 생활 운영 대시보드 + 실시간 행사 관리 도구”

---

## 6. 결론

현재 프로젝트는 초기 기획서의 기본 뼈대는 유지하고 있지만,
실제 서비스는 훨씬 더 실사용성 높은 반 운영 도구 형태로 발전했다.

특히 큰 변화는 다음 세 가지다.

1. 자리 배정 경매를 중심으로 한 운영 시스템으로 발전
2. 노래 큐 기능이 실제 핵심 서비스로 추가됨
3. 메인 대시보드 기반으로 여러 기능을 묶는 구조로 변경됨

반면, 간식 센터나 일반 경매 같은 부분은 아직 초기 기획 대비 프로토타입 수준에 머물러 있어
추가 개발이 필요하다.
